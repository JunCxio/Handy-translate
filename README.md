# Handy-translate

使用自己的大模型或翻译接口，为受支持的游戏生成本地译文。Windows 桌面应用使用 Rust、Tao 与 Wry/WebView2，双击打开独立窗口。游戏运行时读取本地翻译文件，不需要保持翻译服务在线。

## 使用

1. 将 Windows 版完整解压到可写目录，保留 `Handy-translate.exe` 和 `WebView2Loader.dll` 在同一目录，运行 `Handy-translate.exe`。程序直接打开桌面窗口，无需浏览器或命令行窗口。系统需要 Microsoft Edge WebView2 Runtime。
2. 启动后只显示游戏拖入入口。将 `Game.exe` 或游戏文件夹拖入窗口，识别成功后自动显示原文和翻译工作台。也可点击“选择游戏程序”，选择后自动加载。新配置默认在本地自动识别源语言，目标为简体中文；已有语言设置会继续保留。目标语言提供 30 个常用选项，也可选“其他语言”填写语言代码。修改语言后点击“应用语言”；完成切换前禁止翻译和安装，以免操作旧语言项目。
3. 选择 DeepSeek、Codex（本机配置）、Claude Code（本机配置）或自定义服务。Codex 和 Claude Code 自动读取本机 API 地址、密钥与模型；DeepSeek 填入官方地址和模型预设，只需填写自己的密钥。可点击“获取模型”从下拉框选择模型，再点击“测试连接”。点击“保存配置”或开始翻译后保存配置，下次恢复。结果每批校验后自动保存，中断后只继续未完成的文本，更换模型不会重译已有结果。
4. 检查、修改译文，点击“安装译文”。请完全退出并重启游戏。若未全部翻译，剩余文本显示原文。
5. “卸载适配器”移除本工具写入的游戏适配文件及插件注册代码，保留工具中的翻译记录。

“更换游戏”返回拖入入口；也可直接拖入另一个游戏。读取游戏或翻译期间不能切换。每次重新启动都会先显示拖入入口，再次拖入同一游戏时恢复对应的已保存译文。识别失败时留在入口并显示原因。

程序目录的 `data/` 保存翻译记录。移动工具时一起移动这个目录。记录按游戏路径和语言组合隔离；移动游戏或重新解压程序后，若游戏内已安装本工具译文、当前目标语言一致且安装文件校验通过，新建本地项目会按相同原文自动恢复译文。已有项目可点击“恢复游戏内译文”，仅补齐空缺，不覆盖本地修改。安装文件不包含术语表、来源语言和模型策略，恢复不会重建这些信息，也不将恢复结果加入通用翻译缓存。修改语言后需要重新加载原文。

保存译文与安装译文相互独立。即使没有安装到游戏，已显示“本地已保存”的译文也会在关闭或意外退出后保留。再次拖入相同路径、相同语言的游戏会恢复记录。升级时退出旧程序，只替换程序文件并保留原来的 `data/`，不要用空数据目录覆盖它。

工作台顶部将语言选择放在游戏标题旁的独立操作区，引擎标识和“更换游戏”位于标题下方左侧，源语言与目标语言采用更大的分组选择框，目标语言以浅蓝底区分；三个阶段与模块切换并排显示，为原文与译文列表保留更多高度。服务和模型保持可见，地址、密钥等连接细节可折叠；翻译按钮固定在设置区底部。“待翻译”和“失败”按钮可快速筛选文本。安装区会核对游戏内译文的语言、条数、内容和适配器，区分尚未安装、需要更新和已同步。

“启动游戏”位于顶部游戏信息区最右侧，文本与图片页共用；处理期间或游戏没有可启动程序时禁用。文本翻译、图片识别、文字翻译或译图生成本轮全部成功后，Windows 任务栏应用图标会显示绿色对勾，不弹窗、不播放声音。中断、失败或部分素材失败不会显示成功标记；开始下一项任务时清除，重开应用也不会把旧进度当成新完成通知。该标记表示本轮操作成功，不代表译文已经安装到游戏；安装仍需单独执行。

语言、翻译服务、模型、接口、认证、文本筛选和图片识别方式的下拉列表采用统一的圆角面板、浅蓝选中态和滚动条。保留键盘选择、自动识别和自定义语言；较旧的 WebView2 不支持定制原生下拉时使用系统样式。

## 术语表、重译与译文检查

点击列表右上角“术语表”，每行填写 `原文 = 固定译法`，例如 `結衣 = 结衣`。最多 200 项，区分大小写，较长术语优先匹配；术语必须是单行普通文本，不支持变量、控制符、括号和百分号。术语按当前游戏和语言项目保存，重新加载后恢复，导出译文时一并导出。新翻译会保护命中的术语并恢复为固定译法，适用于当前五种接口。

保存或修改术语表不会改写现有译文。点击“检查译文”，查看与原文相同、疑似残留日文假名或韩文、术语不一致、控制标记或长度异常的条目。“待人工检查”筛选只显示已保存译文的疑点；未翻译文本由“未翻译”筛选显示。检查在本地进行，不调用模型、不自动修改结果；人名、语气词等可能被提示，需要人工确认，不代表模型语义质量评估。

每行“重译”可以只处理该条。也可勾选文本或“选择本页”，点击“重译所选”；跨页保留选择，单次最多 500 条，更换游戏或应用语言后清空选择。重译使用当前服务、模型和已保存术语表，可对大模型填写最多 2,000 字符的补充风格要求；DeepL、LibreTranslate 不支持此要求。重译始终跳过缓存复用，成功保存后才替换原译文；失败或中断时尚未成功替换的条目保留原译文。修改后仍需“更新游戏内译文”并重启游戏。

## 翻译缓存

同一游戏的完全相同原文在提取时已合并，只翻译一次。已保存项目会继续跳过已有译文。0.5.0 另在 `data/translation-memory.json` 保存精确匹配缓存，普通续译可跨游戏复用，进度消息显示命中条数；语言、引擎、术语表不同则不会命中，不做相似句猜测或模糊替换。

旧版本已有的有效译文会在加载游戏时加入缓存；新完成结果、手动保存和导入的有效译文也可加入。带补充风格要求的重译结果不会进入普通翻译缓存；已有译文在修改术语后仍属于原术语策略，不会被误当成新术语下的结果。切换模型不会强制清空缓存，需要采用新模型时使用“重译”。

设置区可关闭“复用相同原文的翻译缓存”，普通翻译将跳过缓存读写，项目进度仍会正常保存。相同短句在不同游戏中可能有不同含义，遇到这种情况关闭复用或选中重译。“清除”会移除该项目的译文及当前语言、术语组合的对应缓存；不会清空其他项目已保存的译文。

缓存不保存服务密钥，但与翻译记录一样包含译文，请随 `data/` 一起保留。缓存损坏时会明确提示，可关闭复用继续翻译；不会静默覆盖损坏文件或清空项目。缓存当前最多 64 MB，达到上限后请备份并移走该文件重新建立，或关闭复用。发布包不包含个人缓存。

## 语言识别与覆盖范围

源语言自动识别使用本地语言识别库，从实际提取的游戏文本中抽样，不调用大模型，不增加 API 请求。支持日语、英语、中文、韩语及常用欧洲和亚洲语言；短文本或混合语言无法可靠判断时会提示手动选择。中文自动识别统一使用 `zh-CN`；需要区分繁体等情况时可手动选择。目标语种是否可用取决于所选翻译服务，列表不是服务商支持范围的保证。

自动识别后，项目和缓存始终使用实际语言代码，例如 `ja`，不会建立名为 `auto` 的独立缓存；同一路径、同一实际语言和目标语言会继续使用原有译文。切换到其他目标语言会加载独立记录，切回后恢复原有结果。语言选择可随“保存设置”或开始翻译保存。

进度 100% 表示**已经提取的文本全部生成了译文**，不表示整个画面都已翻译。图片、教程截图、按钮贴图里的文字，以及未适配的插件参数或动态文本不计入该进度。工作台明确提示这一范围，并分别显示本地译文与游戏内安装状态。

本轮检查的测试游戏中，截图对应 `img/pictures/setumei/home_setumei01.png_`：说明框、按钮字样和游戏背景已经合成在整张图片内。它不会经过普通对白绘制入口，需要在独立的“图片素材”模块处理，重复翻译现有文本不能改变该图片。

## 模型调用与费用原则

文本和图片文字统一采用本地处理优先、完全相同原文去重、持久缓存优先、只提交缺少译文的文字、合并批次的流程。普通续译保留已有结果，关闭重开继续；只有用户主动重译才重新提交已有译文。源文件路径和来源记录保留在本地，不随翻译请求上传。请求只包含本批数字编号和待译文字，保留必要的语言、术语和控制符规则；无补充要求时不发送空的风格要求段。

文本在提取时已跨文件合并相同原文；图片先完成本轮识别，再汇总所选范围内的所有待译区域，跨图片精确去重并查同一套翻译缓存。一个原文只提交一次，结果回填到所有对应区域，不覆盖已有译文。文本与图片共用批次规则：按设置的条数和每批 12,000 字符拆分，DeepL 每批最多 50 条，其他服务最多 96 条；不是将所有游戏内容一次发给模型。完成消息显示缓存命中和文本翻译请求次数，次数不等于实际 token 或费用。

图片默认本地 Windows OCR；加载另一个游戏时也恢复本地识别。缺少语言包时在开始前检查并停止，已有识别结果和缓存可继续复用，不会自动转用视觉模型。只有主动选择视觉识别才上传图片。文本先提交正常的首批，成功保存后再按所设并发数处理余下批次，不增加额外测试请求。视觉识别或图片文字翻译请求失败后停止后续请求，保留已完成结果；文本翻译停止派发后续批次并保存已经提交请求的有效返回。不会自动重复请求失败批次。

同一原文可能因剧情语境产生不同译法，精确复用仍需人工核对；可以关闭跨项目缓存或主动重译。不会以模糊合并不同句子来减少调用。

## 图片素材（可选）

默认仍进入“文本翻译”，不会扫描、识别或上传图片。需要处理图片文字时，切换到“图片素材”，主动点击“扫描引用素材”。图片项目、进度、安装和还原独立于文本；与文本共用当前翻译服务、语言和术语表。

1. 扫描 RPG Maker MV/MZ 数据和插件参数中的图片名称引用，再按名称搜索并勾选需要的素材。扫描不会执行脚本或对全部图片 OCR。事件中的“显示图片”与普通名称匹配分别标注来源；名称相同可能出现多张候选，引用也不代表玩家一定能走到该剧情。
2. 需要补充动态文件名时，可主动“开启素材记录”。这会安装独立图片插件；完全重启游戏，经过相关场景，再回来重新扫描。“加载过”只表示曾调用标准图片加载入口，不保证实际显示；未经过的剧情、定制加载器也不会被记录。可单独停止记录，设置变更均需重启游戏。
3. 优先选择本地 Windows OCR，再点击“识别文字”。本地识别不上传图片，需要源语言的 OCR 包；开始前会检查缺包，不会逐图重复失败或自动转用云端。视觉识别会把**所选图片**发送给当前配置的服务，支持 Chat Completions、Responses 和 Anthropic Messages 协议；具体模型必须支持图片输入，纯文本 DeepSeek 模型、DeepL 和 LibreTranslate 不能识图。
4. 点击“翻译文字”，先汇总本次所选图片的全部待译文字、精确去重并查缓存，再批量发送剩余原文给当前文本翻译服务。可先用视觉模型识别，再切换到其他服务翻译；配置位置与文本模块共用。点击图片名称预览原图、核对区域与文字，可修改原文、译文、矩形和颜色，或增删区域；有修改时先“保存区域”。
5. 点击“生成译图”，检查对照预览，再“安装全部已生成译图”。安装全部有效译图，与列表勾选无关；勾选只决定识别、翻译和生成的范围。请完全退出并重启游戏。生成或修改后需重新安装才能同步到游戏。
6. “还原素材”移除独立图片插件、译图和插件注册段，游戏重新加载原素材，文本译文不受影响。本地图片处理结果仍保留；还原也会关闭素材记录，加载日志留在游戏 `.handy-images/loaded.json`，以后可继续复用。

也可点击“一键处理全部”：先识别全部候选，再汇总待译文字、跨图片去重并查缓存、批量翻译、生成译图，自动跳过已识别但未检出文字的图片；未检出文字不代表一定没有文字，可用单步识别重新核对。已有区域、译文和有效译图继续使用，中断后重开可继续；相同图片的空识别结果也会缓存。完成后仍需检查并点击“安装全部已生成译图”，不会自动安装。选择视觉识别时，所有尚未识别的候选图片都会发送到当前服务，包含最终判定没有文字的图片，会产生识别用量；本地 OCR 不上传图片。可勾选“仅看已检出文字的素材”隐藏待识别和未检出文字项。

进入图片页时会检测当前源语言的本地 OCR 组件；“重新检测”可刷新状态。缺少日语包时，点击“安装日语 OCR 包”，在 Windows 弹出的管理员授权中允许后，由系统 DISM 从 Windows 更新源下载并安装 `Language.OCR~~~ja-JP~0.0.1.0`。应用本身不需要以管理员身份运行；只安装 OCR 组件，不安装完整显示语言，不调用模型。需要联网，组织更新策略或系统组件源不可用时可能失败，界面保留错误代码供排查。

安装期间保持程序打开，其他翻译和素材操作暂停；安装完成后自动复检，显示就绪即可继续识别，不自动提交图片翻译。取消系统授权可重试。系统要求重启时会明确提示，不自动重启电脑；先保存工作，再重启并重新检测。组件安装到 Windows，后续打开应用仍可使用，应用会重新检测实际状态。应用内安装当前仅支持日语；其他语言仍需在 Windows 可选功能中安装相应 OCR 组件。也可自行在管理员 PowerShell 执行 `Add-WindowsCapability -Online -Name Language.OCR~~~ja-JP~0.0.1.0`。

首版支持静态 PNG 与 RPG Maker 加密 PNG（`.png_`、`.rpgmvp`），不支持 Ren’Py 图片、动画 PNG、其他图片格式和定制素材加载器。图片最多 16 MB，边长不超过 8,192、总像素不超过 2,400 万。单步操作最多选择 100 张；列表显示前 200 张，可搜索缩小范围。“一键处理全部”覆盖扫描出的全部引用候选（最多 20,000 张），不受勾选和筛选限制，不扫描未引用文件。

生成译图采用**底色覆盖原字后排入译文**，不会自动修复背景；复杂背景、半透明区域和带描边的文字需要人工调整底色、矩形，或外部编辑后导入同尺寸 PNG（界面导入上限 10 MB）。自动排版使用 Windows 微软雅黑；缺字、译文放不下或阿拉伯语等复杂排版会报错，避免静默裁切。视觉模型的坐标和识别内容也需要人工核对。

图片安装通过 `.handy-images/files/` 的译图映射和 `HandyImageTranslator` 插件工作，不覆盖原图，也不写入文本插件的安装清单。文件被其他程序修改时，会停止覆盖或还原并提示检查，保护外部改动。正常更新和卸载游戏版本前，建议先还原文本及图片适配器。

图片项目保存在工具的 `data/images/`，按游戏路径、源语言、目标语言隔离；每张识别结果和每批译文完成后原子保存，未安装也可关闭后继续。图片内容、识别模式、源语言和视觉服务/模型相同可复用识别缓存；区域文字使用现有精确译文缓存。取消图片页缓存勾选会重新识别，但已有译文仍保留；修改区域原文时应同步清空不再适用的译文，再重新翻译。生成文件按内容摘要存储，旧文件不会在保存新版本前被覆盖；需要清理历史图片缓存时先备份 `data/images/`。

从 0.1.0 更新时，将原工具的 `data/` 文件夹复制到新程序旁即可继续使用记录。游戏适配器的内部文件名和安装清单格式保留，支持更新或卸载改名前安装的适配器。`data/webview/` 是桌面界面的 WebView2 缓存。

关闭桌面窗口会结束程序和进行中的翻译请求，已保存的批次仍可继续。尚未完成并保存的请求下次会重新处理，已提交的云端请求可能仍会计费。“完成进行中的请求后停止”会停止派发新批次，等所有已提交请求完成并保存后停止。

## 翻译服务

优先提供以下预设：

| 服务预设 | 读取方式 | 模型选择 |
|---|---|---|
| DeepSeek | 官方 `https://api.deepseek.com`，使用 Chat Completions，显式关闭默认思考以减少等待；用户填写自己的 API 密钥 | 默认 `deepseek-flash`，另有 `deepseek-v4-pro`，可获取服务的实际列表 |
| Codex（本机配置） | `%CODEX_HOME%/config.toml`；未设置时读取用户目录 `.codex/config.toml` | 读取当前 profile 和模型，可获取服务列表 |
| Claude Code（本机配置） | `%CLAUDE_CONFIG_DIR%/settings.json`；未设置时读取用户目录 `.claude/settings.json`；同目录 `settings.local.json` 中的相关配置覆盖用户配置 | 读取模型、`ANTHROPIC_MODEL` 与 `ANTHROPIC_DEFAULT_*_MODEL`，解析 sonnet/opus/haiku 别名；没有具体名称时点击“获取模型” |

Codex 读取当前服务的 `base_url`、`wire_api`、`env_key` 或 `experimental_bearer_token`。需要 OpenAI API 认证时读取 `OPENAI_API_KEY` 环境变量或 `auth.json` 的同名字段。Claude Code 使用 Anthropic Messages 协议，读取 `ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN`（Bearer）或 `ANTHROPIC_API_KEY`（x-api-key）。同时配置两种 Claude 认证时使用 AUTH_TOKEN。用户配置中的相关 `env` 字段覆盖工具继承的环境变量，`settings.local.json` 优先；修改系统环境变量后需重开工具。

这两种本机预设直接调用 API，不启动命令行工具，不执行配置中的脚本或密钥辅助命令，不使用 Codex/Claude 的账号登录令牌。只有账号登录、没有独立 API 凭据时会提示配置缺失。原本机配置文件保持不变。

保存本机预设时只保存来源、地址、认证方式、模型等设置，不另存密钥；下次打开从同一来源重读密钥。若本机地址、协议或认证方式发生变化，界面提示点击“重新读取本机配置”，不会把新密钥用于旧地址。本机预设的地址和认证方式由来源管理；需要手动填写时切换到“自定义服务”。切换预设会清除上一服务的密钥。

自定义服务支持以下接口：

| 接口类型 | 服务地址 | 模型名称 |
|---|---|---|
| OpenAI Chat Completions | 服务商提供的基础地址，通常以 `/v1` 结尾；也接受完整 `/chat/completions` 地址 | 按服务商或本地部署填写 |
| OpenAI Responses | 支持 Responses 的基础地址，通常以 `/v1` 结尾；也接受完整 `/responses` 地址 | 按服务商填写 |
| Anthropic Messages | Anthropic 或兼容服务的基础地址；接受 `/v1` 和完整 `/v1/messages` 地址 | 使用具体 API 模型名；认证可选 x-api-key 或 Bearer |
| 本地 Ollama | 选择 Chat Completions，填写 `http://127.0.0.1:11434/v1` | 已安装并能运行的模型名称 |
| DeepL | 免费 API：`https://api-free.deepl.com/v2`；专业版使用对应地址 | 不需要 |
| LibreTranslate | 自行部署或有权限使用的服务地址，例如 `http://127.0.0.1:5000` | 不需要 |

配置保存在 `data/settings.json`，不依赖界面端口或浏览器存储，重启后会恢复，模型下拉列表和选中项也会保留。DeepSeek 和自定义服务的 API 密钥默认不保存；勾选“使用 Windows 加密记住密钥”并保存后，以当前 Windows 用户的 DPAPI 密文保存。取消勾选再保存会移除密文，当前窗口仍可使用已填写的密钥。换 Windows 账户或电脑后可能需要重新输入密钥，译文记录不受影响。密钥不写入游戏译文或导出文件。

“获取模型”读取服务的 `/models` 列表，供下拉选择。保存配置会同时记住模型列表和选中项，下次无需重新获取；选择“手动填写模型名称”仍可使用未列出的模型。“测试连接”实际翻译一条 `Hello` 文本，检查认证、模型和返回格式，可能产生少量调用费用。使用云端翻译会提交游戏原文和来源位置，接口费用由服务商收取。工具不提供免费模型额度。

大模型接口要求按提示返回指定 JSON。Responses 使用非流式请求并设置 `store: false`，只接受完成状态的文本输出。Anthropic 使用 `anthropic-version: 2023-06-01`、每批最多 8,192 输出 token，只接受 `end_turn` 状态的文本，忽略 thinking 内容；超过输出限制时应降低每批条数。某批次出错会停止派发新请求，保存其余已提交请求的有效结果，然后报告错误；无效译文不会保存为完成状态。请调整配置或手工填写对应译文。每个请求超时为 90 秒；429 与服务端错误最多重试两次。

## 翻译速度

默认每批最多 48 条，同时最多 4 个请求；每批原文尽量控制在 12,000 字符以内，超过该长度的单条文本单独发送。DeepL 每批最多 50 条。展开“翻译速度”可设置 1–8 个并发、每批 1–96 条。小模型或服务限流时应降低并发和批量。大模型请求采用批次内短编号，减少无关输出，保存时仍使用原有文本编号。

批次按返回顺序独立校验并合并到最新记录，每批原子保存，不会因乱序返回覆盖其他批次。实际速度取决于模型、输入长度、服务吞吐和限流，并发不会保证固定加速倍数。跨批次不共享完整剧情上下文。

交付压缩包不包含账号配置、密钥、游戏或个人翻译记录。DeepSeek 当前模型预设依据[官方文档](https://api-docs.deepseek.com/)，实际可用模型以账号和服务返回为准。

## 游戏支持范围

- **RPG Maker MV/MZ**：识别常见游戏根目录与 `www/` 结构；读取标准数据库、地图对白、选项、角色改名文本、地图显示名及系统术语。通过 `Window_Base`、`Bitmap` 和字符串格式化入口显示及测量译文，保留原始游戏 JSON。自定义逐字绘制插件、动态表达式、图片文字需要单独适配，不在首版覆盖范围内。
- **Ren’Py**：需要保留 UTF-8 可读 `.rpy`；读取单行对白、菜单以及常见 `text`/`textbutton` 文本，跳过 `tl`、存档与 Python 块。使用适配脚本在 `Text.set_text` 处理变量前替换字符串，兼容性需要在具体游戏中验证。不解包 `.rpa`，不反编译 `.rpyc`，不提取多行字符串或 Python 动态生成文本。
- **其他引擎**：当前不支持，加载时会明确提示。图片 OCR 与替换目前仅支持 RPG Maker MV/MZ，不提供通用屏幕翻译、原生 DLL 注入和自动字体替换。

同一游戏中的相同原文共用译文，提取位置最多保留三个供本地定位，不随翻译请求上传。相同句子在不同场景需要不同译法时，当前版本需要调整原文或后续增加位置映射支持。变量标记、格式代码和换行必须按原顺序保留，手工编辑和导入时也会检查。

如果中文出现方框或缺字，请使用游戏支持的方式配置包含中文字形的字体。本工具不自动复制系统字体或修改字体配置。文本长度增加也可能需要调整游戏原有窗口布局。

## 安装文件和撤销

安装前请关闭游戏。安装只涉及以下文件：

- RPG Maker：新建 `js/plugins/GameTranslator.js`、`data/GameTranslatorTranslations.json`，并向 `js/plugins.js` 添加带边界标记的插件注册段。
- Ren’Py：新建 `game/zzz_game_translator.rpy`、`game/GameTranslatorTranslations.json`；游戏会自行生成对应 `.rpyc`。
- 安装目录内的 `.game-translator/` 保存安装清单；RPG Maker 首次安装时还保存 `plugins.js.original`。

工具拒绝覆盖未由它管理的同名文件。卸载前核对管理文件的摘要；发现其他修改会停止，避免删除用户改动。`plugins.js` 的其他修改在卸载时保留。请保留 `.game-translator/` 到卸载完成。

“导出”得到带游戏、引擎与语言信息的 JSON，可编辑 `translations` 对象后导入。只导出已完成的译文，未知原文、错误游戏或语言、损坏的控制标记都会导致整次导入被拒绝。

## 从源码构建

需要 Rust 稳定版工具链与 WebView2 Runtime。Windows 推荐安装含 C++ 构建工具的 MSVC 工具链；GNU 工具链使用 LLVM LLD 链接器及可用的 dlltool，且需要将 `webview2-com-sys` 对应版本的 `x64/WebView2Loader.dll` 放到程序旁。本次便携包已包含该加载器。内置图标资源由 MSVC 或 LLD 的 Windows 链接器直接读取。

```powershell
cargo build --release --locked
cargo test --locked
node tests/adapters.test.cjs
node --test tests/workspace.test.cjs tests/images-adapter.test.cjs
python tests/test_renpy_adapter.py
$env:HANDY_TRANSLATE_EXE = "$PWD\target\release\handy-translate.exe"
python tests/test_app.py
```

构建产物为 `target/release/handy-translate.exe`，发布时命名为 `Handy-translate.exe`。界面与适配器内嵌在程序中，运行时无需 Rust 工具链、Node.js 或 Python。MSVC 构建静态链接 WebView2 加载器，GNU 构建需要随附加载器 DLL。测试使用本机模拟接口，不访问云端翻译服务。

可用启动参数：`--data-dir 路径`、`--port 端口`、`--headless`。默认启动桌面窗口，内部接口仅绑定 `127.0.0.1` 的随机端口，使用临时会话令牌，不开放跨域访问。`--headless` 不创建窗口，仅供自动测试使用。桌面窗口限制导航到本应用，不打开外部网页或弹出浏览器窗口。

## 代码结构

- `src/extract.rs`：引擎识别与原文提取。
- `src/translate.rs`：服务协议、标记保护与结果校验。
- `src/install.rs`：适配器安装、更新、清单与卸载。
- `src/assets.rs`：素材引用扫描、加密 PNG 解码、Windows OCR、区域校验与静态译图排版。
- `src/image_api.rs`：独立图片项目、处理任务、识别和译文缓存、预览与导入接口。
- `src/image_install.rs`：图片插件、译图映射与加载记录的独立安装和还原。
- `src/model.rs`：项目数据结构及原子保存。
- `src/settings.rs`：本地配置和 Windows 密钥加密。
- `src/language.rs`：本地源语言识别和实际语言代码映射。
- `src/local_config.rs`：Codex、Claude Code 本机 API 配置读取与密钥恢复校验。
- `src/main.rs`：本地接口、任务状态和程序入口。
- `src/desktop.rs`：桌面窗口、WebView2 与译文导出保存对话框。
- `adapters/`：游戏内接入脚本。
- `web/`：不依赖前端构建工具的本地界面。
- `assets/`：统一的 SVG、PNG、Windows ICO、窗口像素和链接资源。修改图标后运行 `python tools/generate_icon.py`（需要 Pillow）重新生成；正常构建无需 Python。
- `build.rs`：将内置图标资源链接到 Windows 可执行文件。

引擎入口参考：[RPG Maker MV CoreScript](https://github.com/rpgtkoolmv/corescript)、[Ren’Py Text 实现](https://github.com/renpy/renpy/blob/master/renpy/text/text.py)。具体游戏中的插件组合仍须实测。
